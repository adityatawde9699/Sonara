# Architecture

## Current prototype

`sonara.py` is a local command-line orchestrator. It invokes Poppler's `pdftotext -bbox-layout` and parses the result into the versioned `Document`/`DocumentBlock` representation in `document.py`. Blocks carry a stable extraction ID, order, heuristic kind and kind source, source page, and PDF-point bounding box. Extraction notes flag side-by-side regions, repeated blocks, line-end hyphenation, and pages without selectable text. The old `extract_pdf()` text API remains as a compatibility view over the ordered blocks. The default Python Piper path builds a deterministic narration plan and feeds sentence-like units to a persistent Piper worker. The worker loads the model once, receives text over a private local stdin protocol, writes PCM WAV chunks to temporary files, and never receives document text in its process arguments. A bounded producer queue exposes chunks as they finish; Sonara persists each completed chunk under `chunks/<document-hash>/<run-id>/`, also combines them into `speech.wav`, and writes source-span metadata to `audio_chunks.json`. The static HTML player then schedules one chunk at a time, supports document-wide seek/rate/pause, and stores segment/time progress in browser `localStorage` when allowed. Generation still finishes before the player is opened, and browser behavior remains unverified in this environment. An explicit `--piper` executable override retains the compatible CLI path and writes text to a temporary file passed by path. No document text is sent over a network.

The process boundaries are intentionally simple: the Python process owns subprocess lifetimes and temporary input files; Poppler decodes PDFs while local Python adapters extract TXT/TEXT, Markdown, DOCX, and EPUB; Piper owns model loading and synthesis; the frontend owns playback. Failures and stderr are surfaced to the user. Source documents are never modified.

`narration.py` now provides a deterministic, standalone planning API over schema-v1 document blocks. It creates sentence-like units that carry the original block ID and exact exclusive character offsets. Concatenating a block's unit source spans reproduces its source text exactly. The spoken layer collapses safe whitespace, but the source field remains unchanged; line-end hyphen breaks are retained. Headings remain whole units. Other blocks use punctuation boundaries, a finite English abbreviation set, decimal and URL/email protection, and common quote-attribution handling. Conservative English rules expand common abbreviations and measurement units in `spoken_text`; ISO dates and numeric bracket citations require explicit opt-in. Transformation records preserve original substrings and offsets, and explicit pronunciation overrides take precedence. The Tauri app exposes a bounded preview of original and spoken text before reading. Unsupported languages retain their text apart from safe whitespace normalization. Unit labels and pause milliseconds are heuristics, not TTS prosody commands. Unmatched and overlapping explicit overrides are rejected.

Pauses are derived from punctuation, block type, and block boundaries. They are fixed duration hints between synthesized units; no per-sentence speed/noise variation is applied. Current timings are heuristic and require listening evaluation before further tuning.

The default CLI uses `build_narration_plan()` and synthesizes each unit separately. It persists each mapped WAV atomically and exposes a manifest to the HTML player. The player loads the chunks sequentially, translates a global seek position into segment plus local time, applies the selected playback rate, inserts per-unit pause timers, and offers retry/skip after a chunk load error. Browser local storage keys progress by source hash and narration ruleset; blocked storage is shown to the user. The CLI still waits for the complete synthesis pass before presenting the player. The explicit executable override remains one-shot and exposes its combined WAV as one playback segment.

The Piper worker passes `None` for `noise_scale` and `noise_w_scale` by default so Piper applies values from the selected voice's JSON config. Optional `less` and `more` profiles scale those per-voice values to 0.85× and 1.10× respectively (capped at 1.0); they are experiments in synthesis variation, not pitch or emotion controls. The current default remains the voice configuration. `listening_eval.py` creates randomized, RMS-matched participant packs across an eight-passage corpus and keeps the mapping key in a separate facilitator directory. No quality conclusion is implied until listeners submit ratings.

## Phase 5 desktop shell

`src-tauri/` is a Tauri 2.10.3 Rust application with a React and TypeScript frontend in `ui-react/`. Rust invokes the platform's native document picker (Zenity/Kdialog on Linux, AppleScript on macOS, and PowerShell on Windows), validates supported file extensions, and stores the canonical path in managed state. The frontend cannot submit arbitrary source paths or call filesystem APIs. Rust invokes the existing Python CLI with safe argument boundaries and a minimal inherited environment, writes generated audio beneath the per-user app-local-data directory, tracks the Python process, kills its Unix process group on cancellation/window close, and emits a completion event after validating the generated manifest and chunk paths.

The Rust core returns session metadata and a local media URL base to the frontend, but no filesystem paths. To avoid WebKit rejecting WAVs served over a custom media scheme, Rust owns an ephemeral HTTP listener bound only to `127.0.0.1`. It accepts a random per-launch token and an active-session document hash/passage index, verifies the exact Host header and canonical path under `reader-output/chunks/`, and supports bounded byte ranges. The CSP allows the listener as a media source only; the listener shuts down with the window. Reader progress is JSON version 1, atomically written once per second and on controls under app-local-data, keyed by source SHA-256. The last generated session is restored on launch if all its chunks still exist. SQLite is deferred because this prototype has one active session and one small progress record per document.

The Linux Cargo build and Rust unit tests pass. A user reported WebKit media error 4 for the former custom URI audio source; the desktop player now uses the token-scoped loopback HTTP listener. The new playback path awaits a graphical retest. This execution environment cannot connect to its advertised display sockets, so the window and audible playback cannot be launched here. Native picker implementations exist for Linux, macOS, and Windows, but only Linux is currently exercised. Tauri installer bundling is disabled; Python, ONNX Runtime, and model files remain external prerequisites.

## Target component boundaries

- Rust/Tauri: current one-window application lifecycle, selected-document orchestration, child process cancellation, range-limited local audio serving, and JSON progress persistence. Library/history and cross-platform file picking remain future work.
- Document adapters: PDF, DOCX, EPUB, TXT parsing into stable blocks and source locations. The current PDF adapter and schema are in Python; Rust ownership is deferred until the desktop core is introduced.
- Analysis and narration planning: `narration.py` provides deterministic segmentation, structure-aware pause metadata, and reversible spoken-text changes without rewriting source content; preview and synthesis consume the same source-mapped plan.
- TTS adapter: `tts_engine.py` defines capability/audio/chunk contracts. The default Piper adapter runs `piper_worker.py` as one persistent local process per session. JSON-line requests carry text over stdin; audio stays in bounded, temporary WAV chunk files. Cancellation terminates the worker process, including in-flight inference. The CLI cache is keyed by source hash, planner/schema version, runtime/model/config hashes, voice, speed, unit ID and source/spoken text. LRU cleanup removes inactive hash WAVs toward a 512 MiB budget; current-plan entries are protected and may temporarily exceed it.
- Audio: synthesis uses bounded prefetch and temporary chunks; the generated HTML and desktop shell schedule persisted mapped WAVs with a single audio element. The desktop's loopback HTTP handler serves one requested range at a time with a 64 MiB response cap. This avoids holding the whole document's PCM in the frontend, but does not provide synthesis/playback overlap or native device controls. The combined WAV remains for compatibility.
- React/TypeScript: listening workspace, player, history, and settings. The UI requests desktop capabilities through explicit Tauri commands rather than arbitrary filesystem access. A searchable document library remains future work.
- Python: optional isolated AI experimentation/worker only where a tested model integration justifies the boundary.

## Data and ownership

The original file remains user-owned and is read-only to the pipeline. Extracted text is derived data; audio is a regenerable cache. Current block IDs hash page, global order, top-left source position, and block text, making IDs repeatable for the same extraction. Source boxes include page dimensions and point coordinates. JSON serialization is available from the document object but the CLI does not yet persist it. The prototype stores audio and player HTML in the caller-selected output directory and playback position in browser-local storage.

## Errors and cancellation

Poppler extraction has a 100 MiB input limit, 32 MiB stdout cap, 1 MiB stderr cap, and 60-second timeout; failures are actionable and partial extraction output is not passed to TTS. The persistent Piper worker has a model-load timeout, per-unit synthesis timeout, structured errors, and explicit termination on stream cancellation or application close. Its stdin carries request text, while paths/metadata are the only protocol arguments. The compatibility executable override uses a temporary UTF-8 input file rather than putting document text in argv. Inference runs outside any real-time audio callback.

## Known limits

The desktop app supports PDF, TXT/TEXT, Markdown, DOCX, and EPUB; optional OCR applies to scanned PDFs when Tesseract and Poppler are installed. A library database, native audio-device playback, synthesis/playback overlap, voice cloning, and synchronized highlighting are not implemented. Narration rules are finite and heuristic. The CLI creates mapped chunks and a combined WAV before playback. Cache cleanup is limited to inactive cache files; active-plan entries may temporarily exceed the configured budget. Poppler's bbox layout does not encode reliable semantic table/heading structure; category labels are heuristics and multi-column/table-like order can remain ambiguous. PyMuPDF has not been installed or benchmarked. Piper 1.8.0, ONNX Runtime 1.31.0, and the John medium voice are installed locally. PDF corpus extraction and end-to-end synthesis pass. The Tauri desktop window still needs interactive validation in a graphical environment.
